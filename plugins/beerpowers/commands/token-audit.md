# Аудит токенов Codex

`$beerpowers token-audit [project|window]` показывает расход токенов и последние доступные показатели окна аккаунта. По умолчанию выводит оба разреза. Счётчики токенов берутся из явно переданной выгрузки, лимиты доступны через инструмент хоста Codex. Приватные транскрипты, историю сообщений, профили, другие проекты и внешние сервисы для отчёта не открывай. Если выгрузки нет, вызови обработчик без `--input`.

Для `window` и вызова без режима найди инструмент `get_usage_limits` хоста текущего чата. Если он доступен и период включает текущее время, прочитай лимиты. Передай обработчику только `rateLimitsByLimitId` или, при отсутствии этой карты, `rateLimits`. Из каждого окна скопируй `primary` и `secondary` с полями `usedPercent`, `windowDurationMins` и `resetsAt`. Для одиночного объекта сохрани `limitId`. Добавь `observedAt` с текущим временем UTC. Если нужна сводка по выгрузке за окно или пользователь запросил JSON, передай эти поля временным JSON-файлом через `--limits` и удали его после отчёта. Без выгрузки и сохранения отчёта можно показать доступные проценты и границы прямо по ответу хоста. Для исторического периода используй наблюдения из выгрузки. При отсутствии инструмента укажи, что результат для окна зависит от экспортированных снимков.

Из корня workspace запусти [обработчик token-audit](../bin/token-audit.mjs) из проверенного пакета. Получи `$node` по [правилу выбора Node](../reference/node-runtime.md "beerpowers:reference/node-runtime.md") через `BEERPOWERS_NODE` или PATH. В PowerShell команда с заданным пользователем файлом выглядит так.

```powershell
& $node (Join-Path $packageRoot 'bin/token-audit.mjs') project --input $metricsFile --project $projectLabel --top 8
if ($LASTEXITCODE -ne 0) { throw 'Review the metrics export or the reported arguments' }
```

Для POSIX shell — `"$node" "$packageRoot/bin/token-audit.mjs" window --input "$metricsFile"`. Вызов без `project` и `window` включает оба раздела. Для текущего проекта передай `--project` с достоверной меткой workspace из выгрузки. Если соответствие неизвестно, используй указанную пользователем метку или сообщи, что выборка охватывает всю выгрузку. Флаг `--all-projects` также ограничен выгрузкой. `--since` включается, `--until` исключается. Дата без времени означает местную полночь, время без зоны читается в часовом поясе процесса Node. Если пояс пользователя отличается, передай смещение или Z. JSON показывает обе границы в UTC.

## Формат выгрузки

UTF-8 JSONL содержит только проекцию событий со счётчиками. Каждая группа начинается с `session_meta` с настоящим временем начала сессии и стабильным псевдонимом `payload.id`. Необязательные метки `project`, `role`, `model`, `repository` добавляет поставщик выгрузки, когда они известны и постоянны для группы. Указывай `repository` только при достоверном отнесении всей группы к одному репозиторию. Для нескольких групп нужны уникальные ID. Повтор метаданных той же сессии должен совпадать с первой записью. Ниже синтетический пример одной группы.

```jsonl
{"timestamp":"2026-01-15T10:00:00Z","type":"session_meta","payload":{"id":"fixture-a","project":"demo","role":"tester","model":"fixture-model"}}
{"timestamp":"2026-01-15T10:01:00Z","type":"event_msg","payload":{"type":"token_count","info":{"total_token_usage":{"input_tokens":100,"cached_input_tokens":20,"output_tokens":10,"reasoning_output_tokens":0,"total_tokens":110},"last_token_usage":{"input_tokens":100,"output_tokens":10}}}}
{"timestamp":"2026-01-15T10:02:00Z","type":"event_msg","payload":{"type":"token_count","info":null,"rate_limits":{"primary":{"used_percent":8,"window_minutes":300,"resets_at":1768492800}}}}
```

Используй последнее `total_token_usage` в периоде. Из него вычитается последний снимок до начала периода. При старте сессии внутри периода база равна нулю. Если сессия старше периода, а предыдущего снимка нет, дельта неизвестна. При отсутствии нижней границы это итог с начала сессии к последнему снимку в выгрузке. Для узкой границы между двумя снимками весь прирост относится ко времени второго наблюдения. Для точного разбиения нужен снимок на границе. Одинаковые кумулятивные наблюдения не увеличивают результат. Падение счётчика требует сверки с источником.

В одной сессии допускается другой формат учёта — только `info.last_token_usage`, со стабильным псевдонимом `payload.request_id` на каждый запрос. Повтор с тем же ID, временем, счётчиками и измерениями учитывается один раз. Когда присутствуют оба объекта usage, для итоговых токенов берётся кумулятивный. Число запросов для кумулятивной выгрузки известно, если каждое наблюдение счётчиков в периоде явно привязано к запросу. Смена способа учёта внутри одной сессии останавливает разбор.

### Дополнительные измерения запроса

Счётчик Codex даёт входные токены отдельного запроса в `info.last_token_usage.input_tokens`, если это поле сохранено и наблюдение достоверно привязано к `request_id`. Снимки `total_token_usage` сами по себе не дают перцентилей запроса.

Необязательный объект `payload.request_metrics` расширяет обезличенную выгрузку, когда у её поставщика есть разрешённый источник измерений. Это поля формата BeerPowers. Текущий инструмент окон аккаунта их не предоставляет. Указывай только доступные поля наблюдения.

| Поле | Требования к измерению |
| --- | --- |
| `model_ms`, `idle_ms` | Измеренная длительность соответствующего состояния запроса, целое число миллисекунд. |
| `tools` | Полный список интервалов вызовов. Каждый содержит целые `start_ms` и `end_ms` на общей шкале запроса. Пустой массив подтверждает отсутствие вызовов. `read_id` — стабильный псевдоним прочитанного файла во всей выборке. `null` означает, что вызов файл не читал. Отсутствующее поле означает неизвестную классификацию. |
| `cache_write_input_tokens` | Измеренное число записанных входных токенов. Для разреза по TTL нужен отдельный источник счётчиков по TTL. |
| `cost` | Стоимость запроса из применимых данных тарификации. `currency` содержит трёхбуквенный код ISO 4217, `micros` — целое число миллионных долей валюты. Для суммирования требуется одна валюта. |

В проекции достаточно псевдонимов, чисел и меток. При подготовке оставляй вне выгрузки путь файла, содержимое запроса, аргументы и вывод инструмента, а также идентификаторы аккаунта.

## Как читать отчёт

- `project.totals` показывает входные, кешированные входные, выходные, reasoning и суммарные токены по полям источника. Кешированные входные входят во входные, reasoning входят в выходные. `cachedInputPercent` — доля кешированных во входных при положительном знаменателе. `groups` даёт метки проект × роль × модель, `topSessions` — сессии с наибольшим известным `total_tokens`.
- Ноль означает измеренный ноль. JSON `null` означает, что поле или база интервала отсутствуют хотя бы у одной учтённой сессии. Для пустого разреза число подходящих сессий равно нулю, токены неизвестны. Полнота исходной выгрузки остаётся условием расчёта. Известные значения отдельных сессий остаются в `rows`.
- `window.observations` содержит последний снимок каждого `limit_id` в выбранном периоде, источник, время, первичное и вторичное окно. `used_percent`, `window_minutes` и `resets_at` (Unix-секунды) передаются из источника. Остаток в процентах вычисляется как `100 - used_percent`. При наличии длительности начало равно времени сброса минус длительность. `usage` охватывает экспортированные события всех проектов в этом интервале до момента наблюдения. Фильтр проекта на него не действует. Если у событий нет идентификатора корзины лимита, эти счётчики описывают общий корпус. Пробелы выгрузки ограничивают охват окна.
- `project.measurements` и `measurements` в `groups` показывают метрики по идентифицированным запросам. `inputTokens` содержит p10, p50, p90, p99 методом ближайшего ранга и максимум. `repeatedReads` считает дополнительные чтения после первого для каждого псевдонима файла. `maxConcurrentTools` — максимум одновременно активных вызовов внутри одного запроса, рассчитанный по полуоткрытым интервалам. `cacheWriteInputTokens` и `cost` суммируют измеренные значения. Если метрика неизвестна хотя бы для одного запроса в разрезе, её итог неизвестен.
- `--time` показывает первое и последнее наблюдение счётчиков в каждой выбранной сессии и интервал между ними. При наличии измерений отдельно суммирует время модели, инструментов и простоя по запросам. Перекрывающиеся интервалы инструментов внутри одного запроса в сумме учитываются один раз. Одновременная работа разных запросов может давать сумму больше календарного интервала.
- `--by-repo` группирует расход сессий по явной метке `repository`. Сессии без метки вынесены в `unattributed`. Для разбивки внутри многорепозиторной сессии нужно отнесение отдельных запросов к репозиториям.
- `unavailable` указывает недостающие поля или источники для неизвестных метрик. Для billed-токенов нужна метрика списания, для остатка запросов нужна привязка расхода к запросам и единицам лимита. Имена ролей и моделей годятся для сравнения с уставом при достоверных метках.
- В ответе назови источник, период, охват, известные итоги и конкретные ограничения. Если есть данные, приведи крупнейшие сессии или группы, укажи их долю и доступное действие для проверки причины. Сравнивай с указанным пользователем прежним JSON только при сопоставимых фильтрах, единицах и полноте. По умолчанию результат идёт в чат. Только по запросу передай `--json <новый-файл>` для сохранения копии. Существующий файл обработчик сохраняет.
