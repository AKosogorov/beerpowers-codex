# Трекер задач

Из корня workspace запускай `node <package>/bin/tracker.mjs`. Используй Node из установленного пакета среды или из PATH. В PowerShell передавай каждый аргумент отдельно. Адаптер возвращает UTF-8 JSON, ошибки выводит в stderr с ненулевым кодом.

## Выбор адаптера

По умолчанию работает встроенный Яндекс Трекер. Проект может положить в `.codex/bin/` адаптеры `<имя>-tracker.mjs` для чтения и `<имя>-tracker-write.mjs` для записи. Имя начинается с латинской строчной буквы и содержит строчные буквы, цифры и дефисы. Единственный подходящий проектный адаптер выбирается автоматически. При нескольких выполни `adapters read` или `adapters write`, покажи перечисленные варианты и спроси, какой использовать. Передай имя во временной переменной `BEERPOWERS_TRACKER_ADAPTER` во всех вызовах этого маршрута. Для встроенного адаптера допустимо имя `yandex`. Чтение и запись проверяются отдельно.

Проектный скрипт запускается Node из корня workspace. Первый аргумент — `read` или `write`, далее следуют аргументы соответствующей операции из этой инструкции. Результат — один JSON в stdout. При сборке снимка обработчик передаёт `read <КОД> --comments --out <файл> --attachments <каталог>`. Адаптер создаёт Markdown с постановкой и комментариями и каталог обычных файлов, в том числе пустой при отсутствии вложений. Пакет проверяет артефакты и ведёт кеш, digest и принятие самостоятельно. Адаптер записи соблюдает раздел о предпросмотре и возвращает `needs-confirmation` или `ok`. Он отвечает за привязку согласия к плану, повтор запросов и проверку авторства. Выбери скрипт из доверенного проекта.

## Чтение по запросу

По просьбе прочитать задачу вызови `read <КОД>`. Добавь `--comments` для всей ленты или `--comments-limit N` для последних N комментариев. Ноль возвращает всю ленту. Результат содержит `comments` и общий `commentCount`. Без флага `--attachments` вложения не загружаются.

- `read <КОД> --json` возвращает сырой объект задачи.
- `read <КОД> --out <файл>` отдельно сохраняет Markdown. С `--json` сохраняет исходный объект в JSON.
- `read <КОД> --attachments <каталог>` отдельно загружает вложения. Пути указываются от корня workspace через `/`. Встроенный адаптер сохраняет существующие файлы и сообщает о конфликте имён.
- Для постановки с полным набором артефактов, включая следующие сверки, используй preview и accept из раздела ниже.

## Постановка и возврат

1. В `task-start PROJECT-123` прочитай постановку через `preview PROJECT-123`. Возвращаются текст, комментарии с авторством, перечень вложений с SHA-256, путь к свежему снимку, `digest`, `status` и `changes`. Временная копия лежит в `.codex/.cache/task-start/PROJECT-123/`. Автоматический запрос покрывает все страницы комментариев. Отсутствие доступа, HTTP-ошибка, некорректное вложение или неполная загрузка останавливают старт. Сообщи причину. Для работы с предоставленной вручную постановкой запроси текст и комментарии.
2. При статусе `initial` перескажи задачу. При `unchanged` достаточно одной строки. При `changed` сопоставь изменённые поля, комментарии и вложения с текущим preflight, handover и утверждённым дизайном. Укажи, какой пункт объёма добавился, какое решение отменено или какая развилка закрылась. Приведи автора, дату и цитату при наличии в источнике. Согласованное следствие для объёма запиши в preflight. Пересмотр дизайна передай архитектору для plan-delta.
3. Флаг `--preview` у task-start завершает разбор с копией в кеше. При обычном запуске после проверки веток и постановки выполни `accept PROJECT-123 <digest>`. Команда сверяет содержимое кеша и исходный снимок. Рабочие артефакты лежат в `memory/tasks/PROJECT-123/tracker/task.md` и `task-attachment/`. Добавляй в коммит артефактов только изменившийся `task.md`. Вложения и кеш игнорируются Git. Внутренняя команда `sync PROJECT-123` выполняет чтение и принятие свежего снимка за один вызов.

При передаче из разбора в `task-plan` и `task-start` используй показанный снимок. Укажи соответствие ключей и digest в JSON переменной `BEERPOWERS_TRACKER_DIGESTS`, например `{"PROJECT-123":"<digest>"}`. Обработчик `cached PROJECT-123 <digest>` возвращает прежний результат preview. Он сверяет байты кеша и исходной постановки, работает локально только на чтение. При расхождении нужен свежий preview.

## Запись

Вход пользователя — `$beerpowers tracker <что сделать>` или явное поручение в чате. Если действие или ключ неясны, уточни их. Несколько действий выполняй в названном порядке. Загрузи [навык подготовки черновика](../skills/tracker-task/SKILL.md) до любой записи. Тип, очередь и доску установи по запросу, обсуждению и данным проекта. При нехватке данных спроси. Ссылки на задачи проверь через `read`. Для задачи и бага подготовь Markdown по `write template task|bug`, сохрани поле `text` в файл в папке текущей сессии и проверь через `write check <черновик.md>`. Для правки получи текущее описание и поля, подготовь полное новое состояние и покажи изменения. После успешной отправки удали свой временный черновик и верни ссылку на задачу.

Адаптер подписывает описание задачи и каждый исходящий комментарий, включая комментарий к переходу. Для черновика он один раз случайно выбирает стиль и сохраняет выбор при повторном предпросмотре, подтверждении и повторе отправки. Для `gpt-6.2-astra` возможны три варианта.

- `© Кодекс ИИльич Астральный (gpt-6.2-astra)`
- `© Кодекс ВЗаконе, в народе Астра (gpt-6.2-astra)`
- `© Агент Кодекс 006.2: Позывной «Астра» (gpt-6.2-astra)`

В скобках стоит точный ID из последнего `turn_context.model` текущего чата. Если хост не предоставляет эти метаданные, передай установленный для текущего хода ID через `BEERPOWERS_MODEL`. Глобальная модель по умолчанию не подходит. Адаптер проверяет совпадение `BEERPOWERS_MODEL` с метаданными, когда доступны оба значения.

| Действие | Аргументы после `write` |
|---|---|
| Создать или изменить задачу | `create <черновик.md>`, `edit <КОД> <черновик.md>` |
| Комментарии | `comments <КОД> [id]`, `comment <КОД> <файл.md>`, `edit-comment <КОД> <id> <файл.md>`, `delete-comment <КОД> <id>` |
| Связи | `links <КОД>`, `link <КОД> <вид> <КОД2> [--replace]`, `unlink <КОД> <КОД2>` |
| Статус | `transitions <КОД>`, `move <КОД> <переход> [--resolution <ключ>] [--field <поле>=<значение>] [--comment <файл.md>]` |
| Вложения | `attach <КОД> <файл>…`, `detach <КОД> <id>` |

### Предпросмотр и подтверждение

Отдельное подтверждение показанного плана требуется для создания задачи, правки её описания и полей, перехода статуса, добавления или удаления вложения и удаления своего комментария. При удалении комментария покажи его полный текущий текст и автора. Если координатор сам предлагает завести задачу, сначала согласуй предложение одной строкой. После согласия подготовь черновик и отдельно согласуй его. При отказе не повторяй предложение в этом чате.

Добавление и правку своего комментария, создание и удаление связи выполняй по явному поручению, предварительно сверив задачу и конкретные объекты. Добавь `--request <уникальный-id-действия>` последним аргументом встроенного адаптера. Сохрани ID при повторах того же поручения. Для правки и удаления комментария подбери ID через `write comments <КОД>` по автору и первой строке. Если совпадений несколько, уточни выбор. После правки комментария ответь одной строкой «было → стало». Отдельный предпросмотр доступен и для этих операций по запросу пользователя.

Песочница и коннекторы Codex запрашивают собственное разрешение при необходимости. Пройди этот запрос отдельно. Разрешение хоста регулирует выполнение, а согласие в чате подтверждает конкретный план там, где оно требуется.

Для операций с обязательным подтверждением и при явно запрошенном предпросмотре:

1. Запусти операцию записи без `--confirm`. Статус `needs-confirmation` возвращает назначение, содержимое и `digest` без записи в Трекер.
2. Покажи весь план записи прямо в текущем чате. Укажи действие, задачу или очередь, доску, заголовок, тип, исполнителя, остальные поля и связи, когда они применимы. Если исполнитель в черновике отсутствует, так и укажи. Вставь полный текст из `body.description`, `body.text` или `body.comment` с подписью, без сокращений. Перечисли вложения из `attachments`, включая файлы по локальным ссылкам Markdown. Их ссылки при отправке получат ID от Трекера. Для перехода покажи текущий и целевой статус из `transition`, ключ перехода, резолюцию и остальные изменяемые поля. Для замены или удаления связи покажи `currentLink`. Для удаления комментария покажи его ID, автора и полный текст из `comment`.
3. Спроси, подтверждает ли пользователь именно показанное действие и содержимое. Подходит явный ответ в этом чате, например «Подтверждаю создание задачи в показанном виде». Для согласия нужны и показ, и ответ после него. Путь к файлу, `digest`, исходная просьба о записи и просьба внести правки сами по себе согласия не дают.
4. После согласия повтори те же аргументы с `--confirm <digest>` в конце. Подтверждение привязано к точному плану и байтам файлов, включая вложения. Если изменились текст, назначение, поля, вложения или модель, снова выполни предпросмотр, покажи весь новый план и получи новое согласие.
5. После успешной записи адаптер возвращает прежний результат при повторе тех же аргументов с тем же digest или ID. При неопределённом результате проверь фактическое состояние в Трекере. Если действие точно не применилось и план совпадает, повтори с флагом `--retry` непосредственно перед `--confirm <digest>` или `--request <id>`. При частичном успехе обработай оставшиеся шаги отдельно, с подтверждением для операций, где оно требуется. Адаптер сверяет автора перед правкой и удалением комментария.

## Личные настройки

Окружение задаёт `YANDEX_TRACKER_TOKEN`, `YANDEX_TRACKER_ORG_ID`, при необходимости `YANDEX_TRACKER_ORG_TYPE` (`cloud` или `yandex360`). Иначе каждый ключ берётся сначала из личного файла проекта `.codex/yandex-tracker-settings.json`, затем из `$CODEX_HOME/yandex-tracker-settings.json` (по умолчанию `~/.codex`). Образец пустых полей входит в пакет. Настройки заполняет владелец аккаунта. Для doctor достаточно проверить наличие источника без чтения значений. У тестового HTTP-сервера на loopback адаптер использует синтетический токен и организацию.

`bin/tracker.mjs` выбирает адаптер и управляет снимками. Встроенные чтение и запись Яндекс Трекера находятся в `bin/lib/yandex-tracker-read.mjs` и `bin/lib/yandex-tracker-write.mjs`.
