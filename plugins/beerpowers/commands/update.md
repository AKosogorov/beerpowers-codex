# Локальное обновление workspace

`$beerpowers update` переносит правила из уже установленной версии пакета в подготовленный внешний workspace. Используй корень пакета, проверенный единым навыком `$beerpowers`, и рабочий каталог внешнего Git. [Реестр миграций](../reference/migrations.md "beerpowers:reference/migrations.md") задаёт исходные форматы, четыре управляемых блока, штамп устава и каталоги поставляемых копий.

1. Подготовь `$node` по [инструкции выбора Node](../reference/node-runtime.md "beerpowers:reference/node-runtime.md"). Построй план чтением workspace. Покажи исходную и целевую версии, ожидаемые изменения по файлам и именам блоков, конфликты и идентификатор плана. При конфликте сохрани пользовательский текст. Предложи владельцу сверить его с указанным в плане блоком и перенести проектную часть за границы маркеров либо согласовать содержимое вручную. После разрешения построй новый план.

   ```powershell
   $updateHandler = Join-Path $packageRoot 'bin/update.mjs'
   & $node $updateHandler plan
   if ($LASTEXITCODE -ne 0) { throw 'Inspect the update plan and diagnostics' }
   ```

   Если прежняя копия руководства, пресета, правила или дисциплины отличается от текущего пакета, укажи явно каталог распакованного **прежнего** пакета той версии, с которой создан workspace. Для планирования используй `& $node $updateHandler plan --previous $previousPackage`, для согласованного применения — `& $node $updateHandler apply $planId --previous $previousPackage`. Обе команды используют одну и ту же исходную редакцию. Без неё несовпадающая копия считается конфликтом с ручной правкой.

2. Единый план включает изменения engine и дополнения setup по сохранённым командам проверок. Дождись согласия пользователя на показанные изменения. Передай `$planId` из согласованного плана. Команда проверяет актуальность плана перед записью. При изменившихся входах снова покажи фактический план и согласуй изменения объёма. В Git Bash используй `node "$packageRoot/bin/update.mjs" apply "$planId"`.
   Если `advisories` указывает на существующий `.codex/config.toml`, сверь активный профиль с [шаблоном `beerpowers`](../templates/settings/config.toml). Существующий файл сохраняется при `apply`.

   ```powershell
   $updateHandler = Join-Path $packageRoot 'bin/update.mjs'
   & $node $updateHandler apply $planId
   if ($LASTEXITCODE -ne 0) { throw 'Inspect update diagnostics and rebuild the plan' }
   ```

3. Обработчик выполняет `workspace.pl doctor` после заполнения недостающих ресурсов и до записи версий. При прерывании повтори `plan` из того же каталога с той же версией пакета. Сверь оставшиеся операции с ранее одобренным набором и примени план остатка с его фактическим ID. Штамп в [настройках workspace](../reference/workspace.md "beerpowers:reference/workspace.md") записывается последним.
4. Повторно выполни `plan`. Готовность подтверждают пустой план и результат [$beerpowers doctor](doctor.md) из того же workspace. Сообщи версию, применённые блоки и открытые проблемы диагностики. Безопасно завершить повторный вызов с пустым планом уже на этапе чтения.

Обработчик вызывается из установленного пакета. Переустановка пакета, запись скриптов в профиль пользователя и изменение доверия хукам в эту команду не входят.

При откате с более новой версии той же схемы план содержит только два штампа. Покажи это перед применением. Противоречивые штампы требуют установить исходную версию вместе с владельцем.
