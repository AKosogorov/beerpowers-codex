# Инженерная память проекта

Вызов `$beerpowers onboard` из внешнего workspace. Тимлид отвечает за синтез. Для продуктовой памяти предназначен [product-onboard](product-onboard.md).

1. Выполни проектную проверку из [doctor](doctor.md). Прочитай устав, `memory/MEMORY.md`, текущие темы и список отслеживаемых каталогов продукта. Выбери подсистемы по фактической структуре. В пустом проекте перечисли доступные источники и закончи до запуска ролей.
2. Покажи пользователю подсистемы, вопросы, источники и число отдельных исследователей. Для большого проекта предложи разбить исследование: ядро в первом проходе, периферия в следующем. Приступай к fan-out после согласования этого объёма. Если пользователь уже согласовал объём, используй это решение. Если доступен только тимлид, предложи последовательный проход и укажи исполнителя в отчёте.
3. По [правилам передачи брифа](team-up.md) запусти отдельных read-only исследователей только для согласованных подсистем. Собери `role-packet` для роли исследователя. Передай контекст подсистемы и разрешённые для чтения пути. Попроси вернуть точки входа, конвенции, проверки инвариантов и наблюдаемые дефекты с точными ссылками на строки. Область записи исследователей пуста. Каталоги профилей, конфигурацию с секретами и персональные данные для онбординга читать не требуется.
4. Сам проверь прецеденты и противоречия. Заполни только темы, для которых найден материал. При наличии проектной раскладки в `memory/MEMORY.md` следуй ей. Для новой темы выбери [поставляемый шаблон памяти](../templates/memory/MEMORY.md).


5. Для UI найди брейкпоинты по строкам стилей или конфигурации. Сравни их с ширинами из проекта. Покажи непокрытые диапазоны, лишние ширины и записи внутри нужного диапазона, которые не совпадают с его нижней поддерживаемой шириной. Например, 800 не заменяет нижнюю границу 768. Используй [правило выбора границы](../reference/workspace.md#настройки). Изменяй настройки экранов по решению пользователя. Детали сохрани в `tests/frontend.md`.
6. Если добавил записи о долгах, пересобери индекс командой `node <package>/bin/doctor.mjs tech-debt-index` и проверь получившиеся ссылки. Заверши по [правилам записи и проверки](../reference/onboard-memory.md). Верни имена изменённых тем, открытые вопросы, ограничения проверки и следующий участок исследования.

## Правила

Исследователи работают на чтение. Только тимлид записывает факты, проверив их по коду и сверив с текущей памятью. Сохраняй ручные записи и сверяй противоречия по строкам источника. Память дополняет AGENTS.md и README сведениями о конкретных подсистемах. Оставляй краткие факты со ссылками, а подробности выноси в отдельную тему с указателем из индекса. Большой продукт разбирай по проходам, начиная с ядра.
