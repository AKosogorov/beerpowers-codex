# Диагностика проекта

При вызове `$beerpowers doctor --list` выведи только список проверок из `bin/workspace-check.mjs --list` установленного пакета. Эту справку можно открыть до настройки проекта.

Базовый путь использует Perl и Git. При наличии Node выполни также [расширенную локальную диагностику](../bin/doctor.mjs) из корня workspace. Выбери исполняемый файл по [инструкции Node](beerpowers:reference/node-runtime.md).

```powershell
& $node (Join-Path $packageRoot 'bin/doctor.mjs')
```

Покажи строки `fail` с именем файла и действием для исправления, затем `warn` с ожидаемым изменением и `unavailable` с недостающим источником. JSON включает версию и SHA поставки, результаты базовой проверки workspace, расхождения копий и блоков, [проверки конфигурации и памяти](beerpowers:reference/doctor-checks.md), статус браузера и размеры экранов. Состояние установленного браузера отдели от фактического прогона страницы. Укажи, какие дополнительные проверки были доступны. Если Node отсутствует, сохрани результат базовой диагностики и обозначь расширенные проверки как недоступные.

Для отдельной текстовой диагностики конфигурации и памяти запусти [workspace-check.mjs](../bin/workspace-check.mjs) из внешнего корня. Флаг `--list` выводит перечень проверок из любого каталога.

```powershell
& $node (Join-Path $packageRoot 'bin/workspace-check.mjs')
& $node (Join-Path $packageRoot 'bin/workspace-check.mjs') --list
```

Обычный запуск только читает файлы. Для пересборки индекса техдолга используй [отдельную команду](tech-debt-index.md). [Область диагностики и формат пунктов](beerpowers:reference/doctor-checks.md).

Покажи фактические пути к навыку и манифесту, имя и версию пакета, версию и SHA эталона из диагностики установки. Затем проверь открытый каталог:

```powershell
& $perl $handler doctor
```

Сообщи результат для проекта отдельно от результата установки. В каталоге без внешнего workspace укажи, что проектная проверка требует открыть его корень. При неполной настройке перечисли выданные ошибки с путями. Недостающие файлы предлагает восстановить `$beerpowers setup`; исправление существующего конфликтующего файла согласуют с владельцем.

Проверь в фактической схеме Desktop наличие `collaboration.spawn_agent` с `model`, `reasoning_effort` и `fork_turns: "none"`, `collaboration.wait_agent` и `collaboration.followup_task`. Перечисли доступные инструменты и недостающие для обычного lean. В схеме без `agent_type` сообщи режим «роль назначается проверяемым Markdown-брифом по пути». Покажи путь хотя бы одного проверенного файла роли. Сверь ID и событие доверенного PreToolUse для проверки YAML tools у запущенной роли. Границы записи по путям указаны в постановке. [Порядок запуска](beerpowers:reference/team-decisions.md) Диагностика читает файлы, настройки Git и схему инструментов. Фактические запуск агента, чтение брифа, тесты и вердикт проверяются при выполнении задачи.

В выводе проверь по каждому проекту путь, профиль и строку `Project OK` с его командным файлом. Сверь правила игнорирования личных настроек, кеша и вложений через проектную диагностику. На настроенном проекте выполни `& $perl $handler role-packet reviewer`. Для нескольких проектов повтори с `$env:BEERPOWERS_REPO`, равным очередному имени репозитория. Назови проектный бриф, применимое правило или навык и одну проверку из вывода. Для хуков проверь наличие `hooks/hooks.json` и скрипта пакета. Доверие конкретного клиента проверяется в Desktop → Settings → Hooks или через `/hooks` в CLI. Если статус недоступен, укажи «доверие не проверено». Запуск Perl вручную подтверждает обработчик; статус доставки конкретного tool-вызова берётся из события хоста. [Матрица хуков](beerpowers:reference/hooks.md).

Для расширенного Git-маршрута используй `& $node (Join-Path $packageRoot 'bin/git-workspace.mjs') doctor`. Он проверяет локальное обнаружение checkout и общие профили. Для проверки фактов origin есть отдельная читающая команда `profiles`; используй её при разрешённом доступе к выбранным удалённым репозиториям. Укажи, где проверена только конфигурация, а где выполнен пробный запуск интеграции. [Git проектов](beerpowers:reference/git-flow.md)

## Навыки ролей

Перед запуском диагностики передай в `BEERPOWERS_SESSION_SKILLS_JSON` список идентификаторов навыков, реально доступных в текущем чате. Строки `role-skills` показывают проект, роль и имя недоступного назначенного навыка. При неизвестном списке хоста проверка сообщает о недоступности самой диагностики.
