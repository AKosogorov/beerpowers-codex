# Уборка рабочих деревьев

Ориентируйся на [механику рабочих деревьев](../reference/worktrees.md). Обработай `--artifacts` первым. Например, `$beerpowers worktrees-clear --artifacts task SHOP-42` передаёт `task SHOP-42` в `workspace-clean`. Передай следующие за префиксом форму и аргументы по правилам ниже. Без `--artifacts` выполни обычную уборку рабочих деревьев по кодам.

Для обычной уборки из корня рабочего пространства запусти `& $node (Join-Path $packageRoot 'bin/git-workspace.mjs') worktrees-clear @codes`. Без кодов команда проверит все зарегистрированные продуктовые деревья BeerPowers. Сопоставь `candidates` с кодами, путями и ветками. Укажи пользователю SHA, цель, способ подтверждения влитости и причины, по которым дерево остаётся на диске. При недоступном origin останови уборку.

Перечисли пути производных каталогов из `ignoredDerived` и число записей в каждом. При явно запрошенном `--force` передай исходные коды и флаг. Без кодов этот режим охватывает все деревья. Перечисли невлитые и неопубликованные коммиты отдельно. Если пользователь уже разрешил уборку указанной области, повтори тот же вызов с `--apply --confirm <planHash>` в пределах этого разрешения. Если область удаления ещё не согласована, покажи пути и последствия перед применением. При изменившемся плане покажи новый результат. Проверь список `removed`, сохрани данные об оставшихся деревьях. Подробности работы teardown, ignored-файлов и защиты веток приведены в [правилах рабочих деревьев](../reference/worktrees.md).

## Уборка по указанной области

Для удаления каталогов и артефактов используй [workspace-clean](../bin/workspace-clean) из корня workspace. В PowerShell передай путь аргументом выбранному `$node`. В Git Bash форма та же с `node "$packageRoot/bin/workspace-clean"`. Вызов без `--apply` показывает план.

```powershell
$clean = Join-Path $packageRoot 'bin/workspace-clean'
& $node $clean worktree $taskCode --no-cache
& $node $clean output $taskCode --no-cache
```

- `worktree <код>` снимает зарегистрированные деревья через Git-адаптер. `--merged-anyway` разрешает убрать чистое дерево с невлитой веткой. Ветка сохраняется. `--orphan` разрешает удалить дерево задачи без Git-регистрации. Если пользователь согласовал конкретный план зарегистрированных деревьев, передай его `planHash` через `--apply --confirm <planHash>`.
- `orphans` ищет незарегистрированные каталоги с именами продуктов в `worktrees/`.
- `output <репозиторий>` убирает `.output` из основного checkout. `output <код>` охватывает деревья указанной задачи. Если имя совпадает, приоритет у существующей папки задачи. `output` без цели охватывает все продукты и их рабочие деревья.
- `task <код>` убирает `figma/`, `screenshots/` и `tracker/task-attachment/` в `memory/tasks/<код>/`. Папка задачи удаляется, если после уборки пуста.
- `cache` убирает свободные копии мутантов, старые прогоны тестов с завершившимися процессами и старое состояние напоминания о скриншотах. Порог `--keep-days` по умолчанию равен семи дням. Этот шаг выполняется и после других форм. Передай `--no-cache`, если уборка ограничена остальными путями.

Форма `cache` и флаг `--keep-days` включают уборку кеша. В остальных формах `--artifacts` передай `--no-cache`, если пользователь не запросил кеш явно. Сохрани этот флаг, если пользователь уже его указал.

Когда пользователь разрешил уборку указанной области, передай `--apply` одним вызовом для соответствующей формы. Проверь вывод и код возврата. Файлы под Git внутри артефактов, вложенные репозитории и ссылки защищены проверками утилиты.

При обычной уборке включи в отчёт сухой прогон `workspace-clean cache` даже при отсутствии кандидатов. Применяй кеш отдельно только в согласованном объёме. Для осиротевшего каталога проверь Git-метаданные, перечисли пути и предложи выбор владельцу. После согласования вызови `workspace-clean worktree <код> --orphan --no-cache`, затем ту же форму с --apply. Если дерево считается активным после конфликтного переноса патча, проверь статус MR на хостинге. Для merged сверь источник, SHA и цель, назови доказательство и используй согласованный scoped --merged-anyway. Уборка деревьев сохраняет ветки по умолчанию: покажи владельцу оставшиеся refs и предложи `git branch -d <ветка>` для подтверждённой влитой ветки. После самостоятельной уборки напомни о retro для артефактов влитых задач.
