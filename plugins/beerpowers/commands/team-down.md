# Остановка команды

При нескольких проектах задай `$env:BEERPOWERS_REPO` и выполни `pause` или `clear` для каждого затронутого checkout отдельно. Постановка в `memory/tasks/<имя>/preflight.md` общая. Пауза, отчёты и feature-курсор выбранного проекта лежат в `memory/tasks/<имя>/repos/<репо>/`. При одном проекте они остаются непосредственно в каталоге задачи.

`$beerpowers team-down [<имя>]` завершает текущий цикл. При вызове без имени определи задачу по активной работе, фактической ветке проекта и сохранённому preflight. При неоднозначности останови передачи и уточни имя до записи. Для lean и feature работай из внешнего workspace. Пользовательская остановка в произвольной формулировке действует так же.

1. Прекрати выдачу новой работы. При немедленной остановке или незавершённом эпике останови работающие роли **этой задачи** через `collaboration.interrupt_agent` и проверь прекращение записи. Сохрани частичный результат и открытые проверки. При штатном завершении оставь участников доступными для ретро до шага 4. В новом чате опирайся на файлы.
2. Выполни локальный повторный вход обработчика без JSON постановки, как описано в [task-start](task-start.md). Возьми из вывода `Source` и `Handover digest`. Проверь ветку, исходный SHA, diff, индекс и незаписанные файлы, preflight и отчёты по [правилам сверки](team-lazy.md). У фичи также прочитай [маршрут](../reference/feature-implementation.md) и состояние через `feature-state <имя>`. Зафиксируй открытый гейт, владельца, режим C/D и требуемый следующий артефакт. Законченную работу зафиксируй один раз. Код в полёте оставь в checkout. Укажи проверенные пути, незакоммиченные части и роль, которая их получит. Не приписывай задаче посторонние изменения.
3. При незавершённой работе сохрани **один** раздел `## Пауза` в `memory/tasks/<имя>/handover.md`. Используй фазу `design`, `impl`, `test` или `review`, сделанное с SHA, состояние работы в полёте, владельца-роль, блокеры и конкретный следующий шаг. Отметь ограничение пользователя и непроверенное. В preflight сохрани подтверждённые гейты, SHA и причины принятых решений. Старое активное указание этапа 4 пометь исполненным или замени ссылкой на handover, сохранив исторические факты и авторский текст. Текущий план остановки живёт в handover.

   Из корня workspace задай проверенные значения и выполни в том же PowerShell, что подготовку `$perl` и `$handler` из навыка. Текстовые поля — однострочные значения. После изменения HEAD перечитай состояние.

   ```powershell
   $pause = @{
       head = $sourceSha; digest = $handoverDigest
       date = (Get-Date -Format 'yyyy-MM-dd'); phase = $phase
       done = $done; owner = $owner; in_flight = $workInProgress
       blockers = $blockers; next = $nextStep
   }
   $env:BEERPOWERS_HANDOVER_JSON = $pause | ConvertTo-Json -Compress
   & $perl $handler handover $taskName pause
   if ($LASTEXITCODE -ne 0) { throw 'Pause was not saved' }
   ```

4. Для локального завершения фичи требуется `Next: done` и неизменные доказательства. При локальном завершении сверь последнее полное тестирование и последнее ревью, включая постановку, команду, базу и полный diff. Для старых отчётов 0.4.0 действуют те же правила. Прочитай **фактические** SHA, код выхода и вердикт из этих конкретных записей. Если хотя бы один гейт открыт, используй `pause` при остановке. Для lean перед `clear` доведи до конца [возобновление QA](team-lazy.md#возобновление-qa), включая повторный вход без раздела паузы. При записи недостающего финального гейта в preflight закрой прежнее активное указание о паузе. В уже завершённой задаче оставь исторические записи как есть.

   ```powershell
   $finish = @{
       head = $sourceSha; digest = $handoverDigest; base = $reviewBaseSha
       tested = $fullRunSha; exit = $fullRunExit
       reviewed = $reviewedSha; verdict = $lastVerdict
   }
   $env:BEERPOWERS_HANDOVER_JSON = $finish | ConvertTo-Json -Compress
   & $perl $handler handover $taskName check
   if ($LASTEXITCODE -ne 0) { throw 'Completion evidence needs reconciliation' }
   # Перед clear выполни ретроспективу завершённого эпика.
   & $perl $handler handover $taskName clear
   if ($LASTEXITCODE -ne 0) { throw 'Completion evidence needs reconciliation' }
   ```

   После успешного `check` и перед остановкой участников вызови [retro](retro.md) по точному коду. Используй статус, план и дистилляцию, попроси доступных участников передать уроки по их гейтам. При повторе проверь уже дистиллированный `evidenceId`. Здесь выполняется фаза сбора уроков. Уборка требует отдельного решения. После ретро останови оставшиеся роли, перечитай состояние и выполни `clear`. При срочной остановке незавершённого эпика пропусти ретро и сохрани паузу.

5. Сверь результат обработчика и diff внешнего Git. Фиксируй отдельным коммитом только проверенные изменения задачи, сохраняя чужие файлы и индекс. При прерывании после записи файла сначала проверь, нужен ли ещё этот коммит. Если раздел уже снят и отчёты сохранены, верни прежний итог. Сообщи пользователю остановленные роли, стадию, владельца, блокеры, следующий шаг или локальный финиш. **Заверши вызов.**
