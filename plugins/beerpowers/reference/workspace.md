# Контракт движка с workspace

[Setup](../commands/setup.md) записывает настройки и управляемые блоки. [Update](../commands/update.md) мигрирует их. [Doctor](../commands/doctor.md) проверяет локальный workspace. Обработчики запускаются из корня внешнего Git, где лежат `.codex/` и `memory/`.

## Каталоги

| Путь | Назначение |
|---|---|
| `projects/<репо>/` | Основные checkout проектов. Адаптер обнаруживает непосредственные подкаталоги с собственным `.git`. Имя проекта сохраняется в настройках и рабочих деревьях |
| `worktrees/<код>/<репо>/` | Зарегистрированные checkout задач. См. [рабочие деревья](worktrees.md) |
| `memory/tasks/<код>/` | Постановка, подтверждения, checkout и отчёты. См. [раскладку артефактов задачи](tasks-layout.md) |
| `docs/features/<slug>/` | Артефакты [PM-конвейера](feature-pipeline.md) |

Внешний Git версионирует память, конфигурацию и документы фичи. Setup добавляет `projects/` и `worktrees/` в его ignore. Общие пути в конфигурации задаются относительно корня workspace, с прямым слэшем. Личные настройки интеграций и медиа задачи остаются под gitignore.

## Настройки

`.codex/workspace.json` хранит `schemaVersion: 1` и `beerpowers` с версией установки. Диагностика требует корректной версии и распознаёт исходный формат 0.2.0. Настройки UI читают [CDP и layout](integrations.md), настройки тестов — [параллельный запуск](parallel-tests.md) и [мутационные пробы](mutants.md).

```json
{
  "schemaVersion": 1,
  "beerpowers": "0.10.0",
  "ui": true,
  "viewports": [
    { "name": "mobile", "width": 375, "height": 667, "mobile": true },
    { "name": "desktop", "width": 1440, "height": 900, "mobile": false }
  ]
}
```

По умолчанию CDP использует mobile 375×667 и desktop 1440×900. В проектном списке имена и ширины viewport должны быть уникальны. Для каждого диапазона вёрстки бери нижнюю поддерживаемую ширину, а для мобильного диапазона включай `mobile`. Источник ширин — Tailwind, UI-кит или глобальные media queries проекта. Высота задаёт окно испытания, включая сгиб, sticky и модалки. [Setup](../commands/setup.md) принимает подтверждённые размеры, [onboard](../commands/onboard.md) сверяет их с кодом.

| Файл | Что хранит |
|---|---|
| `.codex/git-settings.json` | Профили проектов и общие настройки [маршрута Git](git-flow.md) |
| `.codex/git-settings.local.json` | Личные параметры публикации |
| `.codex/role-settings.json` | Состав, пресеты и карта правил по путям |
| `.codex/barriers.json` | Переключатели хуков и `comments.excludeDirs`. См. [контракт хуков](hooks.md) |
| `.codex/figma-settings.json`, `.codex/yandex-tracker-settings.json` | Личные настройки [интеграций](integrations.md) |

`comments.excludeDirs` принимает массив путей каталогов от корня workspace, например `["projects/store/generated"]`. При проверке комментариев хук игнорирует этот каталог и все вложенные пути. Для checkout в `worktrees/<код>/<репо>/` используется тот же путь проекта. В конфигурации хранится исключение именно для `guard-comments`.

## Управляемые блоки и установленный пакет

Управляемые блоки в `AGENTS.md`, `.codex/team-charter.md`, `.codex/team-lead.md` и `memory/MEMORY.md` отмечены маркерами движка. Проектный текст сохраняй за границами блоков. Миграция сверяет старый штамп и содержимое, показывает конфликт ручной правки и сохраняет проектные расширения. [Доставка инструкций](instructions.md) · [Миграции](migrations.md)

Хуки, двоичные помощники и reference читаются из выбранного установленного пакета. Используй [проверяемое разрешение пути пакета и рантаймов](command-runtime.md) вместо копирования помощников в проект. Свои setup и teardown проект хранит в `.codex/bin/`. Формы, аргументы и повторный вход описаны в [рабочих деревьях](worktrees.md).

## Кто читает настройки

Setup записывает подтверждённые размеры окна и проектные сведения. Скрипты CDP читают `ui` и `viewports`, тестовые адаптеры — `tests`, Git-адаптер — профили проектов из `git-settings.json`. Личные параметры публикации загружаются из `git-settings.local.json`. Хуки используют общие переключатели из `barriers.json` и проектные сигналы из `workspace.json`. Общие настройки можно коммитить, токены и параметры персонального аккаунта остаются локальными.

Контракт setup и teardown рабочих деревьев задаёт [reference/worktrees.md](worktrees.md). Формы записи, подтверждения и свой адаптер трекера определены в [tracker](../commands/tracker.md). Если после миграции остались ссылки на старые копии, выполни [doctor](../commands/doctor.md).

## Кеш и диагностика

`.codex/.cache/` игнорируется внешним Git. [workspace-clean](../commands/worktrees-clear.md#уборка-по-указанной-области) убирает свободные копии мутантов, старые завершённые прогоны тестов и старые отметки скриншотов. Порог по умолчанию семь дней. Длительности тестов, снимки и состояние адаптера трекера, данные открытия задачи и служебное состояние защитных проверок сохраняются. Незнакомые каталоги требуют отдельного разбора.

Запусти [doctor](../commands/doctor.md) или `node <пакет>/bin/workspace-check.mjs` из корня. Список проверок доступен с `--list`. Ошибка формата или раскладки отображается с путём к файлу. [Проверки workspace](doctor-checks.md)
