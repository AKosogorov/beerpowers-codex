# Доставка инструкций в Codex Desktop

## Установка из локального каталога

В Codex Desktop пакет BeerPowers доступен в каталоге `akosogorov-codex` после регистрации локального marketplace. Открой PowerShell в корне этого репозитория.

```powershell
$checkout = (Get-Item -LiteralPath .).FullName
codex plugin marketplace add $checkout --json
if ($LASTEXITCODE -ne 0) { throw 'Не удалось добавить каталог плагинов' }
codex plugin add beerpowers-codex@akosogorov-codex --json
```

После обновления клона повтори команду `codex plugin add`. Затем в Codex Desktop открой **Settings → Hooks**, сверь источник и доверь нужные определения. [Как проверить события и срабатывания](hooks.md)

Команды работают из внешнего workspace. Тимлид читает настройки и формирует пакет для конкретной роли. Каждая строка `FILE` содержит путь и SHA-256 фактических байтов. Для файлов проекта путь указан от корня workspace, для навыков указан абсолютный путь в пакете. Сразу за строкой идёт содержимое файла. После изменения путей или инструкций соберите пакет заново.

| Механизм | Область | Как проверить |
|---|---|---|
| Три правила ответов | Основная сессия с доверенным плагином, в том числе вне настроенного workspace. `SessionStart` читает три файла `rules/reply_*.md` установленного пакета | В новой сессии проверьте контекст хука. Выключайте по одному через `BEERPOWERS_REPLY_BLOCKING_ASKS`, `BEERPOWERS_REPLY_FILE_LINKS`, `BEERPOWERS_REPLY_USER_SHELL` в окружении процесса Codex. Значение `false` отключает соответствующее правило. |
| Корневой устав | Один внешний workspace | Проверьте два добавленных блока в `AGENTS.md`. Другие Markdown-файлы читаются явно. При запуске из другого корня сначала укажите внешний workspace. |
| Бриф роли | Проектный агент | `role-packet reviewer` передаёт `.codex/agents/reviewer-agent.md` и применимые проектные правила. Тимлид задаёт фазу, проверяемый SHA и границы работы. |
| Состав команды | Поле `team` в `.codex/role-settings.json` и устав команды | По умолчанию доступны девять профильных ролей. В lean минимальную правку вносит тимлид. `team-up` сообщает фактически подтверждённые роли и очередь. |
| Пресеты | Поле `stacks` того же файла. Пакет подбирает текущую роль во всех включённых стеках | Проверьте Laravel, Nuxt, PostgreSQL, Supabase, Elasticsearch, GitLab по исходникам. В JSON используются `laravel`, `nuxt`, `postgres`, `supabase`, `elasticsearch`, `gitlab`. Распознавание читает отслеживаемые манифесты, включая вложенные. Для конфигураций, описанных в CI, compose или README, уточните выбор вручную. Сверяйте пункты пресетов с установленными зависимостями. |
| Правила для путей | Карта `rules` связывает проектный текст `.codex/rules/<имя>.md` с конкретными файлами или каталогами. Ручная привязка `.` означает весь продукт. При неизвестном объёме пакет включает все активные правила выбранного продукта | Запустите команду с двумя разными путями. Из внешнего корня укажите продукт через `BEERPOWERS_REPO` и относительные к checkout пути. Для `projects/api/app/File` и `worktrees/SHOP-1/api/app/File` передайте один аргумент `app/File`. Каталог `app` охватывает `app/File`. Если роль открывает другой слой, обновите пакет. |
| Память роли | Индекс и `feedback_*.md` только своей роли в `.codex/agent-memory/<роль>/`. Для tester действует тот же формат | Добавьте в тестовом workspace пример обратной связи. Попросите роль назвать цитату из файла и её область действия. Общие знания идут в `memory/`, состояние задачи — в `memory/tasks/`. |
| Навыки | Codex подбирает навыки по запросу. Пакет роли также включает общие и профильные навыки по их абсолютным путям | Для frontend проверьте, что выведены `skills/minimal-diff/SKILL.md`, `skills/economy/SKILL.md` и `skills/page-screenshot/SKILL.md`. Внешние навыки используются при наличии. |
| Передача и изоляция | Для нового участника тимлид выбирает `fork_turns: "none"`, передаёт абсолютные пути, фазу и допустимые записи. Участники работают в общем checkout | До работы получите имя прочитанного файла и специфичное для него требование. Проверьте по выводу пакета, после работы сверьте diff. Ограничения записи по ролям содержатся в брифе. Разрешения и песочницу определяет хост. Для независимого dry-run и оппонента используется отдельный свежий контекст с ограниченным набором входных данных. |
| Хуки | Доверенные обработчики получают отдельные события хоста | Доступные решения, пропуски событий и безопасные фикстуры перечислены в [таблице хуков](hooks.md). |

## Проверка на своём проекте

В PowerShell подставьте пути из вывода `$beerpowers doctor` в переменные `$perl` и `$handler`. Следующая команда из внешнего корня печатает пакет без записи:

```powershell
& $perl $handler role-packet reviewer 'app/Http/Invoice.php'
```

В Git Bash при заданном `packageRoot`:

```bash
perl "$packageRoot/bin/workspace.pl" role-packet reviewer 'app/Http/Invoice.php'
```

Для проверки именно доставки вызовите `$beerpowers team-up` на тестовом workspace с уникальной фразой в памяти одной роли. Сравните её ответ с проектным файлом. Для автоматической проверки обновления, фильтра путей, стека, памяти и байтов пакета в checkout есть `tests/codex-roles.t`.

[Порядок загрузки AGENTS.md в Codex](https://developers.openai.com/codex/guides/agents-md) и [схема хуков](https://developers.openai.com/codex/hooks).
