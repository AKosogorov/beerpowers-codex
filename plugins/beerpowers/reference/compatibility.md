# Совместимость с исходным BeerPowers v2.20.0

Версия и ревизия исходного BeerPowers закреплены в [манифесте Codex](../.codex-plugin/plugin.json). Явный вызов [`$beerpowers`](../skills/beerpowers/SKILL.md) открывает документ выбранной команды. Ниже указаны тесты из каталога `tests/` checkout. Работу конкретного человека, согласие на checkpoint и ответы живых ролей проверяют отдельно в фактической сессии.

## Переход со старых команд

| Раньше | Как выполнить в этом пакете |
| --- | --- |
| `worktree-add <репо> <КОД> [база]` | Из внешнего workspace запусти `bin/git-workspace.mjs` через Node. Сначала `task-plan <КОД> --repo <репо> --worktree`, затем `task-start` с теми же аргументами после проверки плана. Имя релизной базы на origin укажи как `<КОД>@<ветка>`. Для проектной базы действуют правила `git-flow.md`. Флаги `--copy-env` (после согласия владельца), `--no-deps` и аргументы хука после `--` описаны в [правилах рабочих деревьев](worktrees.md "beerpowers:reference/worktrees.md"). В чате подготовку задачи ведёт [$beerpowers task-start](../commands/task-start.md). |
| `tasks-status [--fetch] [--remote]` | Запусти через Node `bin/retro.mjs status [КОД ...] [--fetch] [--remote]`. По умолчанию сводка читает локальные данные. Для каждого проекта проверь давность наблюдения. Значение флагов и поля JSON описаны в [сводке задач](retro-status.md "beerpowers:reference/retro-status.md"). |

У [ретроспективы](../commands/retro.md) флаг `--force` меняет план уборки рабочих деревьев. Для удаления папки задачи по-прежнему требуются свежая проверка влитости всех затронутых проектов, разбор памяти и согласие владельца. [Уборка деревьев](../commands/worktrees-clear.md) оставляет локальные ветки. Удаление конкретной влитой ветки через `git branch -d` согласуется отдельно.

[$beerpowers update](../commands/update.md) обновляет workspace, подготовленный этим портом. Поддерживаемые версии и границы замены указаны в [реестре](migrations.md "beerpowers:reference/migrations.md"). Для проекта Claude Code или qtim автоматической конвертации старого устава, настроек разрешений, ролей и хуков нет. При переходе подготовь отдельный workspace через [setup](../commands/setup.md), выбери проекты и перенеси согласованные проектные знания вручную.

## QA и интеграции

При включённом UI doctor завершает работу с ошибкой, если браузер отсутствует. Для параллельных тестов doctor выполняет пробную раскладку на этой машине и проверяет ресурсы мутаций. Фикстуры с пустой выборкой, отсутствующим браузером и отслеживаемым файлом мутаций проверяются в `codex-doctor.test.mjs`. [Проверки](doctor-checks.md "beerpowers:reference/doctor-checks.md")

После правки файла хук выбирает первую подходящую строку правил, включая альтернативы `*.vue|*.ts`. Setup добавляет команду проекта в правила найденного стека. Пустой файл сохраняет выбор отключить напоминания. Срабатывание на событиях проверено входными данными хука в `codex-hooks.t`. [Хуки](hooks.md "beerpowers:reference/hooks.md")

Вход и артефакты располагаются в workspace. Исполняемый файл поставляется в пакете. |
| Laravel + Nuxt | `tests/codex-example.t` создаёт временную песочницу с двумя учебными Git-репозиториями, проверяет обнаружение стеков, команды тестов и повторный setup. | Проверка использует заглушки манифестов и локальные тестовые данные. |

Полный локальный прогон из корня checkout запускает `node .github/scripts/validate_codex.mjs`. Локальные фикстуры проверяют содержимое временного версионированного кеша и идемпотентность обновления workspace. После обновления проверьте доверие и блокировку в новом чате Desktop по [сценарию для хуков](hooks.md "beerpowers:reference/hooks.md").
