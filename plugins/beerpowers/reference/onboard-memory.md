# Запись результатов онбординга

Сначала перечитай целевой файл. Найди существующую запись по смыслу, сущности и источнику. Совпадение пропусти. При изменении поведения проверь обе версии и покажи пользователю конфликт со строками источника. Согласованную поправку внеси точечной правкой. Сохраняй записи людей, порядок разделов и материал предыдущих проходов, в том числе при повторе после прерывания. Создавай новую тему только при наличии факта или конкретного вопроса.

Добавь строку на каждый новый вывод. Пример для внешнего workspace с репозиторием `store`:

```markdown
- Факт: состояние заказа задаёт перечисление OrderStatus. `projects/store/app/OrderStatus.php:8`
- Гипотеза: менеджер использует тот же набор статусов в отчёте.
- Вопрос: где зафиксирован порядок состояний в отчёте?
```

Для факта укажи существующую строку локального источника в `projects/<репо>/`. В продуктовом треке допустима ссылка на строку предоставленного документа или на весь документ в `docs/product-context/`, если вывод опирается на документ целиком. Проверь сам источник и ближайший контекст. При нескольких источниках заключи каждый `путь:строка` или путь к документу в отдельные обратные кавычки. На каждую тему добавь одну относительную Markdown-ссылку в `memory/MEMORY.md`. Гипотезы и вопросы оставляй с явной меткой. В разделе «Белые пятна» индекса укажи пропущенную подсистему и причину.

Из корня workspace проверь все затронутые темы. Передай их фактические пути отдельными аргументами. Для повторного прохода без изменений можно проверить уже учтённые темы с такими записями. В PowerShell подготовь `$node` по [инструкции выбора Node](node-runtime.md) и выполни команду выбранного трека.

```powershell
$check = Join-Path $packageRoot 'bin/onboard-check.mjs'
& $node $check onboard memory/project/project-map.md
& $node $check product-onboard memory/product-actors.md memory/product-metrics.md
```

[Проверка](../bin/onboard-check.mjs) читает только индекс, устав, выбранные темы, PM-бриф в продуктовом треке и источники указанных фактов. Код 0 подтверждает ссылки индекса, допустимую область темы и существование указанных строк. Семантику подтверждает тимлид. В ответе назови число фактов, источники и белые пятна. Заверши проектной командой [doctor](../commands/doctor.md); успешная строка `Project OK` в итоговом ответе также закрывает окно `guard-user-files` при активном Stop-хуке. Если хук недоступен, те же ограничения точечных правок соблюдает тимлид.
