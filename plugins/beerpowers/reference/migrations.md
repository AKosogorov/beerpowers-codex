# Обновление структуры рабочего проекта

Для переноса из BeerPowers Claude действует [отдельная инструкция](claude-migration.md).

Исходную версию берут из поля `beerpowers` файла `.codex/workspace.json` во внешнем workspace. Целевая версия — поле `version` [манифеста установленного пакета](../.codex-plugin/plugin.json). Поле `upstream.version` фиксирует происхождение порта.

| Исходная версия Codex | Формат на входе | Переход |
| --- | --- | --- |
| `0.2.0` | Исходный объект с единственным полем `beerpowers`, без `schemaVersion` | Сверить и применить блоки ниже, затем записать числовое `schemaVersion: 1` и целевую версию. |
| `0.3.x` и последующие до целевой версии | Числовое `schemaVersion: 1` | Перенести блоки до целевого состояния и обновить `beerpowers`. Сохранить прочие пользовательские поля конфига. |
| Текущая версия пакета | Числовое `schemaVersion: 1` | Сверить блоки, копии и штамп с исходной редакцией (baseline). Совпадающие файлы пропустить. При полном совпадении план пуст. |

При понижении версии для schemaVersion: 1 сверь оба штампа и покажи план отката. После согласования обнови только штампы устава и workspace.json. Шаблоны, роли, память и копии сохраняются. При неизвестной схеме или противоречивых штампах остановись на диагностике.

| Целевой файл workspace | Имя блока | Поставляемый шаблон |
| --- | --- | --- |
| `AGENTS.md` | `entry` | [Вход в устав](../templates/AGENTS.md) |
| `.codex/team-charter.md` | `codex-team` | [Обязанности команды](../templates/charter/team-charter.md) |
| `.codex/team-lead.md` | `codex-lead` | [Гейты тимлида](../templates/charter/team-lead.md) |
| `memory/MEMORY.md` | `codex-memory` | [Индекс памяти](../templates/memory/MEMORY.md) |

Каждый файл в `templates/engine/` содержит один именованный HTML-комментарий `beerpowers:engine` и закрывающий `/beerpowers:engine`. Свежий setup берёт блоки из этих файлов. Генератор полного индекса памяти подставляет тот же блок `codex-memory` в каркас индекса. Каркасы устава, брифа и индекса задают начальный проектный текст.

Область замены определяется парой имя файла + имя блока. Старый setup уже добавлял `entry` в `AGENTS.md`. Ранее созданный текст вне маркеров, включая исходный текст прежних каркасов, считается проектным. Обновление устава и брифа дополняет его блоками. Для существующего общего индекса без маркера действует исключение ниже.

| Состояние известного блока | Действие |
| --- | --- |
| Блок отсутствует при первой миграции | Добавить канонический блок в целевой документ. Существующий общий индекс без `codex-memory` сохранить. |
| Содержимое совпадает с целевым шаблоном | Оставить содержимое, учесть в baseline. |
| Блок совпадает с известной прежней редакцией | Обновить по целевому шаблону. |
| Содержимое изменено внутри блока и отличается от целевого шаблона, происхождение текста подтвердить нельзя либо разметка неоднозначна | Вывести конфликт. Ручное разрешение выполняют до применения. |
| Блок другого имени или другого трека | Сохранить целиком. |

При миграции в устав добавляется штамп `generated-by: beerpowers-codex v<версия> · mode: plugin-linked`. Обработчик сверяет его при последующих обновлениях. Ручной текст вне этих участков сохраняется побайтово, включая переводы строк и отдельный блок доставки пакета роли. В workspace с общей памятью существующий индекс без метки `codex-memory` сохраняется побайтово.

План включает дополнения текущего setup для сохранённых команды и источника из `memory/commands/<репо>.md`. Так старые workspace получают недостающие брифы, настройки и указатели за одно согласование. Перед записью версии update выполняет проектную проверку `workspace.pl doctor` с заполненными ресурсами. При ошибке старый номер версии сохраняется. Уже записанные целые файлы учитываются при следующем плане.

Codex и `role-packet` читают навыки из `skills/<имя>/SKILL.md` установленного пакета. Если старый setup уже создал `.codex/disciplines/`, его файлы сохраняются побайтово. Ссылки из старых задач и ручные правки остаются доступны по прежним путям.

Правила в `.codex/rules/` принадлежат проекту. Обновление снимает ссылки на прежний встроенный шаблон при совпадении имени, точного текста с учётом CRLF и автоматически назначенных путей. Сам файл сохраняется. Ручной текст и изменённые охваты остаются в конфиге.

Setup собирает плоские брифы под `.codex/agents/`. При обновлении сохраняются ручные брифы и прежние файлы в `.codex/roles/`. Состав команды, настройки, команды тестов и проектные интеграции остаются во владении проекта. [Порядок применения и проверки](../commands/update.md).

## Локальная проверка реестра

Из корня checkout BeerPowers Codex выполни `node .github/scripts/check_migrations.mjs --base <коммит>`. Для проверки локальных правок подойдёт `HEAD`, для всей серии правок укажи её исходный коммит. Проверка требует доступную Git-ревизию и включает отслеживаемые изменения и новые неигнорируемые шаблоны.

Если дифф меняет поставляемый шаблон или соответствующую генерацию, добавь или обнови запись с заголовком `## <версия>`. Версия должна совпадать с полем `version` манифеста Codex. Опиши, что изменилось в workspace, и перечисли в обратных кавычках имена всех затронутых управляемых блоков из таблицы. Для нового блока добавь также строку в таблицу соответствий. Пары маркеров проверяются в соответствующих шаблонах. Изменения проектного текста в существующих каркасах устава, брифа и индекса сами по себе не требуют записи.

## 0.10.1

- Корневая точка входа остаётся в блоке `entry`. Точные исходные блоки доставки пакета и выбора checkout удаляются при setup или update. Ручные блоки требуют сверки.
- В уставе `codex-team` и индексе `codex-memory` пересборка техдолга относится к отдельной команде. Старые явные вызовы продолжают работать.
- Setup определяет короткие имена памяток по действующему каталогу запуска и сохраняет содержимое. Старые поля ролевых настроек читаются. Стек для новых checkout берётся из манифестов. Известные точные формы сгенерированных quality-gates обновляются, проектные маски остаются во владении команды.
- Смысловые правки устава и брифа `codex-lead`, существующих памяток и индексов памяти переносятся по [инструкции миграции из Claude](claude-migration.md).

## 0.10.0

- Управляемые блоки перенесены в основные шаблоны. Подтверждённый контекст заменяет общее описание роли. Setup создаёт плоские проектные брифы в `.codex/agents/`. Существующие брифы, руководства и пресеты в `.codex/roles/` сохраняются. Новый устав возвращает таблицу владельцев памяти и закрытый список артефактов. Пустой индекс техдолга сразу совпадает с машинным выводом doctor.

Setup принимает согласованные заметки Discovery для первичного заполнения карты проекта, памяток команд и проектных запретов. Существующие документы памяти остаются во владении проекта. Бриф тестера задаёт выпуск и передачу QA-чеклиста для применимой задачи после финального APPROVED.

Блок `entry` передаёт из `AGENTS.md` путь к уставу и правила загрузки инструкций. `codex-team` задаёт обязанности ролей, `codex-lead` — порядок проверок и передачи задачи. `codex-memory` связывает индекс с проектными знаниями и памятью задач.

Setup указывает версию в копиях руководств и пресетов. Update добавляет метку к прежним копиям после проверки их содержимого.
