# Проверка экрана и скриншоты

В личном браузере работай в своей вкладке. Существующие вкладки, профиль и процессы принадлежат пользователю. Для воспроизводимого прогона и снимков на диске запускай свой Chromium с отдельным временным профилем и свободным портом. После работы закрой только этот экземпляр через `cdp-screenshot.mjs --close` на том же порту.

В сценарии `cdp-run.mjs` проход и проверка результата разделены. Прочитай каждую строку JSONL и сравни состояние DOM с ожидаемым для этой ширины. Успешный клик сам по себе не подтверждает результат. Каждый сценарий получает чистый браузерный контекст. Подготовь его данные заново, если они зависят от cookies или localStorage.

До проверки UI установи адрес локального dev-сервера из его вывода, проверяемый маршрут, состояние тестовых данных и ширины из задания или документации проекта. Для штатной формы запуска открой память команд репозитория. Не останавливай чужой сервер и не включай в кадр секреты или личные данные. Выбери доступный реальный браузер или принятый в проекте браузерный runner.

1. Открой реальную страницу и нужное состояние, дождись отображения данных. Для мобильного сценария задай нужный viewport и touch при наличии. Фиксируй размер окна и фактическую ширину контента.
2. Выполни реальное действие пользователя, включая ввод, tap, scroll или переход. Для многошагового пути запиши состояние до и после, наблюдаемые результаты, сообщения консоли и ошибочные ответы сети. Отдели ожидаемый отказ от неожиданной ошибки. При моках укажи, какой ответ заменён и что этим можно доказать.
3. Для каждого затронутого экрана и назначенной ширины сохрани кадр в `memory/tasks/<код>/screenshots/`. Используй различимые имена, например `front-cart-loaded-1440.png` и `tester-cart-error-390.png`. Для тестера и разработчика — отдельные результаты. Открой сохранённую картинку, проверь экран целиком, обрезание, наложения, фокус и состояние после действия. Для точного размера дополнительно запиши измерение DOM.
4. В отчёте укажи маршрут, состояние, размеры, действия, наблюдения, путь к кадру и что осталось непроверенным. Если доступный инструмент умеет только показывать картинку или читать DOM, явно укажи ограничение по сохранению. Требование достоверного снимка остаётся открытым.
5. Закрой только собственный временный сеанс. На повторной проверке UI-исправления пересними затронутый сценарий. Для прогона без UI укажи причину отсутствия новых кадров.

Для проверки диффа используй `bin/layout-check.mjs <код> <репо>`. Для реальных действий запусти `bin/cdp-run.mjs <сценарии.json> --out <результаты.jsonl>` с `SCREENSHOT_TASK=<код>`. Для отдельного кадра с измерением DOM используй `bin/cdp-screenshot.mjs` с отдельным профилем и портом. Макет для визуального сравнения сохраняет `bin/figma-export.mjs <ссылка на фрейм> --save <код>`. Исполняемые файлы находятся в проверенном пакете. Аргументы PowerShell, коды завершения и поля результата приведены в [инструкциях по интеграциям](../../reference/integrations.md "beerpowers:reference/integrations.md").
