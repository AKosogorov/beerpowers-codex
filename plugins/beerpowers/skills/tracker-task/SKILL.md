# Черновик задачи или бага для трекера

Когда нужно составить текст для человека, запиши его в локальный черновик в папке текущей сессии. Форму возьми из поля `text` результата `bin/tracker.mjs write template task|bug` установленного пакета. Отделяй пользовательское поведение от технической справки.

В шапке укажи наблюдаемый результат в заголовке задачи или симптом и место в заголовке бага, тип, слой и реальные зависимости по ключам. Обязательные поля очереди бери из проекта. Дата — абсолютная, решение — с автором и датой. Не придумывай очередь, ключ, ставку, оценку, исполнителя и реквизиты сессии.

| Задача | Баг |
|---|---|
| Кто решает какую проблему, в каком окружении и на каком экране | Где обнаружен дефект, версия, роль, устройство и ширина |
| Ссылки на конкретные страницы и кадры макета | Шаги и частота для обычного функционального дефекта или как обнаружен чтением кода |
| Что меняется в поведении, точные названия полей и тексты | Что наблюдали и какое поведение ожидалось, источник ожидания |
| Критерии приёмки «кто — действие — результат» | Доказательства, влияние, известный обход |
| Подтверждённые границы и связанные задачи | Подтверждённые границы и регрессии |

Технические детали вынеси в `<код>-tech.md`. Запиши контракты, имена модулей, ограничения, отвергнутые варианты, риски и пробелы. Ссылки и подписи умести рядом с затронутым пунктом. Удали секреты и персональные данные из текста и вложений. Для security-находок приведи проверяемые строки кода и защитное исправление. Для согласованного изменения объёма сохрани дословное решение с датой.

## Поля и шапка

- Тип определяет пользователь. Укажи очередь, числовой ID доски и тег слоя для разработки. Логины исполнителя, QA и ревьюера ставь при наличии, иначе оставь «—». Для тегов `Frontend` и `Backend` используй суффиксы `(front)` и `(back)`. Для обоих слоёв подготовь две задачи со связью «зависит от».
- Свяжи каждый ключ из описания. В поле «Связи» укажи вид и ключ, разделяй связи точкой с запятой. Виды связей перечислены в форме адаптера. Связанные задачи прочитай через `bin/tracker.mjs read <КОД>`.
- Перед первой секцией при наличии зависимостей добавь блоки «Зависит от» и «Блокирует». Для задачи назови ключ и чего ждём, для внешней зависимости укажи что нужно и от кого.
- В блок «⚠️ При выкладке» включи действия для работы на стенде и разрушительные последствия для существующих данных и сценариев. Этот текст используется после открытия MR.

## Секции задачи

| Секция | Содержание |
|---|---|
| Цель | 2–4 предложения о том, что увидит или сможет сделать пользователь |
| Контекст | Текущее поведение и основание для изменения, например ТЗ или датированное решение |
| Где | Полный URL каждой затронутой страницы на стенде и в рабочем окружении, если страница уже существует. Для новой страницы укажи будущий URL и отметь текущий 404. Для состояния укажи фильтр, вкладку или шаг. Для сквозного элемента приведи конкретную страницу. Ссылка на макет ведёт на фрейм Figma с `node-id` |
| Что делаем | Пункт на изменение поведения, с точными текстами, полями и числами |
| Критерии приёмки | «Кто — что делает — что видит». Критерий должен проверяться наблюдением. При риске регрессии добавь проверяемое прежнее поведение |
| Вне объёма | Связанная с постановкой работа, которую делают по другому ключу или исключили с указанной причиной |

Секция «Где» нужна для страниц и экранов. «Контекст» и «Вне объёма» добавляй при наличии материала.

## Секции бага

| Секция | Содержание |
|---|---|
| Где | Полный адрес страницы, стенд, роль, устройство, браузер и ширина. Для бага API укажи метод и полный адрес |
| Шаги воспроизведения | Нумерация от открытия страницы, одно действие на шаг и частота. Для находки по журналу, коду или ревью используй секцию «Как обнаружено» |
| Фактический результат | Наблюдаемый симптом |
| Ожидаемый результат | Ожидание и его источник, например ТЗ, макет или прежнее поведение |
| Доказательства | Снимок с выделенным местом или запись последовательности действий. Приложи доказательство к этой задаче |
| Влияние | Затронутые пользователи, обход, влияние на релиз и известный момент появления |
| Вне объёма | При необходимости укажи ключ отдельной задачи или причину исключения |

## Справка и комментарии

Оставь описание на языке продукта. Для бага API допустимы метод, адрес и код ответа. В технической справке укажи место по имени модуля, функции или компонента. Номера строк и SHA в долгоживущей справке устаревают. Привяжи справку обычной локальной ссылкой из соответствующего пункта. Изображение помести рядом с описанием наблюдения. Адаптер загружает локальные файлы по путям от каталога черновика и подставляет ссылки трекера.

Убери оценку, бюджет и ставки из описания и справки. Вопросы, оценки и принятые решения идут в комментарии. Решение, меняющее объём, требует правки постановки и комментария.

Комментарий — отдельный Markdown без полей и секций. Для правки подготовь полный новый текст, ID найди через `write comments <КОД>`. Подпись ставит адаптер по модели текущей сессии. Следуй диагностике адаптера, если модель недоступна.

Черновик и его вложения храни в каталоге файлов текущей сессии. Если хост не показывает путь сессии, используй отдельную временную папку для этого чата. Указывай абсолютный путь к черновику. Снимок постановки существующей задачи хранится по правилам команды task-start.

Проверь черновик задачи или бага через `bin/tracker.mjs write check <черновик.md>`, затем перепроверь смысл и данные. Работа по навыку заканчивается готовым черновиком. Для отправки по поручению пользователя следуй [маршруту трекера](../../commands/tracker.md).
